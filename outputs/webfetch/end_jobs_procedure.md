END\_JOBS procedure
===================

Last Updated: 2026-07-14

The END\_JOBS procedure ends a set of active jobs specified by a set of
filters.

This procedure uses the End job (ENDJOB) CL command to end the selected jobs in controlled
groups. This can prevent the system from being overwhelmed by a huge number of requests at the same
time.

**Authorization:** See Note below.

![Read syntax diagram](/docs/en/ssw_ibm_i_76/rzajq/./c.gif)[![Skip visual syntax diagram](/docs/en/ssw_ibm_i_76/rzajq/./c.gif)](#skip)

The schema is SYSTOOLS.

job-name-filter
:   A character string expression that contains an unqualified job name to use to determine the jobs
    to be ended.
:   The special value of \*ALL indicates that all jobs are eligible to be ended. This is the
    default.
:   When this parameter is not specified or has a value of \*ALL, a value must be provided for
    *current-user-list-filter* or *subsystem-list-filter*.

current-user-list-filter
:   A character string expression that contains a list of up to 10 user profile names separated by
    exactly one comma. The filter determines which current user values to use to find jobs to be
    ended.
:   If this parameter is not specified, jobs for all users are eligible to be ended.

subsystem-list-filter
:   A character string expression that contains a list of up to 25 subsystem names separated by
    exactly one comma. The filter determines which subsystems to use to find jobs to be ended.
:   If this parameter is not specified, jobs in all subsystems are eligible to be ended.

end-option
:   How to end each job.

    CONTROLLED
    :   The job ends in a controlled manner. This allows the program running to perform end-of-job
        processing. This is the default.

    IMMEDIATE
    :   The job ends immediately and the system performs end-of-job cleanup.

end-controlled-delay
:   When *end-option* is CONTROLLED, the number of seconds to wait before ending a job with the
    IMMEDIATE option.
:   The value can be from 1 to 999999. The default is 30.

delete-spooled-files
:   Whether the spooled files generated by the job being ended are kept or deleted.

    NO
    :   The spooled files created by the job being ended are kept for normal processing by a writer.
        When the job ends, the spooled file action (SPLFACN) job attribute determines whether spooled files
        are detached from the job or kept with the job. This is the default.

    YES
    :   The spooled files created by the job being ended and which are on output queues in the library
        name space of the thread ending the jobs are deleted. The job log is not deleted.

maximum-joblog-entries
:   The maximum number of entries in the message queue of the job being ended that are written to
    the job log.

    *integer*
    :   The maximum number of messages that can be written to the job log. A value of 0 indicates that
        no job log should be generated.

    \*NOMAX
    :   All messages on the job message queue are written to the job log.

    \*SAME
    :   The job's message logging limit does not change. This is the default.

job-end-maximum
:   The maximum number of jobs to end. The default is no maximum.

job-end-iteration-count
:   The maximum number of jobs to end in a single iteration. The default is 100 jobs.

job-end-iteration-delay
:   The number of seconds to delay between end job iterations. The default is 60 seconds.

Note
----

This procedure is provided in the SYSTOOLS schema as an example of how to end a group of jobs.
Similar to other Db2® for i provided tools within SYSTOOLS, the
SQL source can be extracted and used as a model for building similar procedures, or to create a
customized version within a user-specified schema.

Services provided in SYSTOOLS have authorization requirements that are determined by the
interfaces used to implement the service. To understand the authority requirements, extract the SQL
for the service and examine the implementation.

Example
-------

* Find and end all the active jobs with a job name of BATCHTEST. For every job, end using the
  controlled option, save any spooled files, and do not generate a job log. With the knowledge that
  there are a limited number of jobs with this name, all of them will be ended in a single iteration
  using the default iteration size of 100.

  ```
  CALL SYSTOOLS.END_JOBS(JOB_NAME_FILTER          => 'BATCHTEST', 
                         END_OPTION               => 'CONTROLLED',
                         DELETE_SPOOLED_FILES     => 'NO',
                         MAXIMUM_JOBLOG_ENTRIES   => 0);
  ```
* Find and end all the active jobs in the QBATCH subsystem that ANGELA is running with a job name
  of RUNAWAY. End 20 jobs at a time, with a 15 second delay in between requests to end groups of 20
  jobs. For every job, end using the immediate option, do not save any spooled files, and do not
  generate a job log.

  ```
  CALL SYSTOOLS.END_JOBS(JOB_NAME_FILTER          => 'RUNAWAY', 
                         CURRENT_USER_LIST_FILTER => 'ANGELA', 
                         SUBSYSTEM_LIST_FILTER    => 'QBATCH',
                         END_OPTION               => 'IMMEDIATE',
                         DELETE_SPOOLED_FILES     => 'YES',
                         MAXIMUM_JOBLOG_ENTRIES   => 0,
                         JOB_END_ITERATION_COUNT  => 20,
                         JOB_END_ITERATION_DELAY  => 15);
  ```
* Find and end up to 2000 active jobs in the QBATCH subsystem that ANGELA is running with a job
  name of RUNAWAY. End 50 jobs at a time, with a 30 second delay in between requests to end groups of
  50 jobs. For every job, end using the immediate option, do not save any spooled files, and do not
  generate a job log.

  ```
  CALL SYSTOOLS.END_JOBS(JOB_NAME_FILTER          => 'RUNAWAY', 
                         CURRENT_USER_LIST_FILTER => 'ANGELA', 
                         SUBSYSTEM_LIST_FILTER    => 'QBATCH',
                         END_OPTION               => 'IMMEDIATE',
                         DELETE_SPOOLED_FILES     => 'YES',
                         MAXIMUM_JOBLOG_ENTRIES   => 0,
                         JOB_END_MAXIMUM          => 2000,
                         JOB_END_ITERATION_COUNT  => 50,
                         JOB_END_ITERATION_DELAY  => 30);
  ```
